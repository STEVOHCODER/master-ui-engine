Cards

Containers that group related content and actions with consistent elevation. Media, body and action row are separate slots, so a card grows in one place and stays aligned in another.

Name: Cards
Category: cards
Framework: Vanilla HTML/CSS/JS
Defined in: styles/components.css #cards (+ #badges, #buttons, #utilities)
Variants: default, elevated, outlined, featured, interactive
Slots: card-media, card-body, card-tag/title/desc, card-actions
Responsive: auto-fit columns; the card never sets its own width
Dependencies: none
License: MIT

Variants

Elevation is a choice, not a default: .card sits on a hairline, .card-elevated drops it for a shadow, .card-outlined goes the other way. .card-interactive opts a card into the hover lift, because only a card you can actually click should promise one.

Responsive behavior

The grid, not the card, decides the column count. .grid-auto is repeat(auto-fit, minmax(16rem, 1fr)), so three columns become two at tablet width and one on a phone without a single media query. Media keeps a fixed 16/10 aspect ratio, and every text slot is min-width: 0 so a long title wraps instead of pushing the card wider than the viewport. .card-actions carries margin-top: auto, so a short card still pushes its buttons onto the same baseline as a tall one — pair it with .spread to split label left, action right.

Accessibility

  • Decorative card artwork is inline SVG marked aria-hidden="true", so screen readers skip it
  • Links and buttons stay real elements — a card is not a div with a click handler
  • .card-interactive and a.card get a 2px :focus-visible ring with a 3px offset
  • A badge conveys state with text, not colour alone
  • Sufficient contrast between text and card backgrounds in light and dark
