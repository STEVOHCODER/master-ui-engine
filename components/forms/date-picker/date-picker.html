Date Picker

Select a date using the native date input with consistent styling.

Name: Date Picker
Category: forms
Framework: Vanilla HTML/CSS/JS
Defined in: styles/components.css #fields (the popover is the platform's)
Design system: MASTER-UI-ENGINE custom
Variants: default, with min/max, required
Responsive: yes — full-width
Dependencies: none (native <input type="date">)
Original source: MASTER-UI-ENGINE (original)
License: MIT

Default

An ordinary .field: label, control, helper. The calendar itself is not markup on this page — clicking the field or its glyph hands the job to the platform picker, whose day cells are already keyboard and touch operable.

When should this begin?

With constraints

min and max are enforced by the picker, so days outside the range are simply not selectable — no validation script on this page. required blocks form submission and is announced by the field's own message.

Earlier days are greyed out by the platform picker.

This field is required.

Responsive behavior

The control is width:100% with min-width:0 from the sheet, so it shrinks inside a narrow form without overflowing at 320px, and it grows to --control-h-lg on touch devices. Mobile browsers swap the desktop calendar for their own wheel or calendar sheet.

Accessibility

  • Native <input type="date"> is keyboard and screen-reader supported, including segment-by-segment editing
  • Associated <label> via for/id; the message is joined with aria-describedby
  • Visible focus ring from the sheet, and the picker glyph brightens on focus
  • aria-required plus the constraint attributes state the rule before the user submits
  • color-scheme: dark from the engine re-paints the open calendar in the dark palette
