File Upload

A drop target that is still a form control. The dashed box is decoration; the thing you click, drag onto and Tab into is a real <input type="file">, which is why this component needs no JavaScript to work.

Name: File Upload
Category: forms
Framework: Vanilla HTML/CSS/JS
Defined in: styles/components.css #dropzone (+ #fields, #buttons, #utilities)
States: default, hover, focus-within, .is-dragging (app-toggled), populated list
Slots: dropzone, dropzone-input, dropzone-icon/title/link/hint, dropzone-list, file-row
JS needed: only to render rows from input.files and toggle .is-dragging
Dependencies: none
License: MIT

Multi-file

The transparent input is stretched across the whole target, so every pixel of the dashed box opens the picker and every pixel of it is a valid drop zone. The list below is what an application renders from input.files: name, size, and a remove button with a 44px hit area.

Drag-over and single file

.is-dragging is the only state the sheet cannot reach on its own: an application adds it on dragover and removes it on dragleave. It is shown here statically so the treatment is visible. The narrow target below is the same component for one image.

Wiring it up

Nothing in styles/mue.js touches this component, deliberately: the native control already does the hard parts. The application code is two listeners plus one render loop, and it never has to fake a click.

Script
zone.addEventListener("dragover", (e) => {
  e.preventDefault();
  zone.classList.add("is-dragging");
});
zone.addEventListener("dragleave", () => zone.classList.remove("is-dragging"));
zone.addEventListener("drop", (e) => {
  e.preventDefault();
  input.files = e.dataTransfer.files;
});
input.addEventListener("change", () => render(input.files));

Accessibility

  • The control is a real file input, so Tab, Enter and the OS picker work with no JS at all
  • It is labelled by a .sr-only <label>, not by the visible decoration text inside the box
  • :focus-within puts a 3px ring on the whole target, so keyboard focus is obvious even though the input itself is invisible
  • File size and file count are text, and the remove button carries an .sr-only name that includes the file it removes
  • Remove buttons and the target are 44px and 88px tall respectively
  • Long names truncate with an ellipsis; the size and the button never get pushed off at 320px
