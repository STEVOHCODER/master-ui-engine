Form controls with labels, validation states, helper text, and accessible associations.

Default states

A field is a column: label, control, then optional helper text. The control takes its 44px height, border, surface and focus ring from the sheet, so the label and the input can never drift apart in size.

We'll use this to personalize your dashboard.

Native select: it still opens with a click or the keyboard.

Validation states

Error and success states with associated messages. The state class goes on the .field wrapper, so the control and its message change colour together.

This username is already taken.

Email looks good.

Disabled controls drop out of the tab order.

Responsive behavior

Every control is width:100% with min-width:0, so a long value wraps instead of pushing a horizontal scrollbar. Below 640px the page padding tightens, and on touch devices the controls grow to --control-h-lg.

Accessibility

  • Every input has a programmatically associated <label> via for/id
  • Error fields use aria-invalid="true" and aria-describedby pointing at the message
  • Visible focus ring: 2px outline plus the --ring-focus halo (WCAG 2.4.7)
  • 44px minimum control height, so the field is a valid tap target
  • Disabled inputs are non-focusable and get a sunken surface, not just grey text
Markup
<div class="field">
  <label class="field-label" for="email">Email address</label>
  <input id="email" type="email" placeholder="alex@example.com">
  <p class="field-helper">We'll use this to personalize your dashboard.</p>
</div>

<div class="field is-error">
  <label class="field-label" for="username">Username</label>
  <input id="username" type="text" aria-invalid="true" aria-describedby="username-err">
  <p class="field-msg" id="username-err">This username is already taken.</p>
</div>
