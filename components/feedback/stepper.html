Stepper

Where a multi-part task is, in progress. The rail is drawn by the sheet and the three states are classes, so a wizard is markup plus two lines of application code and never a canvas.

Name: Stepper
Category: feedback
Framework: Vanilla HTML/CSS/JS
Defined in: styles/components.css #stepper (+ #display for the timeline variant, #utilities)
States: is-done, is-current (aria-current="step"), is-upcoming
Slots: stepper, stepper-item, stepper-dot, stepper-label, stepper-name, stepper-text
Responsive: vertical under 640px, horizontal above; one media query
Dependencies: none; state swapping is the app's two class toggles

Responsive behavior

The default is the vertical form: a continuous rail on the left, dot and label as a two-column row, comfortable even at 320px. At min-width: 40rem the same items become grid columns of 1fr each, which makes the rail maths exact without measuring anything: each step draws its incoming segment from -50% of its own width to its own centre, so the segment always lands dot to dot. That is the only breakpoint in the component, and the label text is min-width: 0 so a long step name wraps instead of widening the row.

Accessibility

  • The list is a real <ol>, so reading order is the step order
  • The active step carries aria-current="step", which screen readers announce and the sheet styles as well
  • Dot numbers and check glyphs are aria-hidden: the step name in the label is the accessible name, so nothing is announced twice
  • Done is a filled dot with a glyph, current is ringed, upcoming is dashed - three shape differences, so state never depends on color alone
  • Rows clear 44px via --control-h min-height, so a step row is tappable
  • Both themes hold AA: dot borders use --border-medium, labels --text-primary and --text-secondary
