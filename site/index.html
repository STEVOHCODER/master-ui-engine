01 — The problem

Agents ship code that works and interfaces that look alike.

A model asked for “a dashboard” produces the dashboard it has seen most often: the same cards, the same spacing, the same blue. It is functional. It is not designed.

Without the engine

  • Repetitive layouts on every screen
  • Generic cards and dashboards
  • Inconsistent typography, spacing and colour
  • Responsive behaviour invented per page, usually badly
  • Common patterns regenerated from scratch each session
  • Interfaces that work but do not feel designed

With MASTER-UI-ENGINE

  • 54 previews that already render, theme and reflow
  • One token layer: colour, type, spacing, motion, borders
  • 31 copy-ready CSS units with documented names
  • Real mobile audit notes per preview, not promises
  • Retrieve a tested starting point and adapt it
  • Consistent output across agents, models and projects

03 — Same design, other houses

Fourteen of those components also exist as React, Vue and Web Components.

A port is not a second design system. design-tokens/engine.css and styles/components.css stay the only place colour, spacing, radius and motion are decided; a framework folder contributes markup, focus handling and state for that framework. No binding ships its own stylesheet, its own theme or a CDN request — the React and Vue galleries below run on bundles built inside this repository and committed with it.

engine/frameworks/react/preview/index.html 1280 px

Three real galleries, one per stack, running the same shared stylesheet. Svelte and Angular have architecture documents and zero source files, so they are absent from this frame and labelled planned in the support matrix instead of faked.

01

React experimental

14 components under frameworks/react/ — buttons, inputs, textareas, selects, checkboxes, radios, switches, cards, badges, avatars, dialogs, dropdowns, tabs, accordions, tables and notifications. Built with esbuild, exercised in headless Chrome on 2026-11-01: 16 gallery sections, zero remote requests, no double-bound vanilla script. Not published to npm — you copy the folder.

02

Vue experimental

The same 14 as single-file components in frameworks/vue/, built with Vite (25 modules, a 103 KB committed bundle) and checked in headless Chrome the same day with no console errors. Composition <script setup>, emits declared, native attributes fall through.

03

Web Components experimental

21 <mue-*> elements in frameworks/web-components/, deliberately light DOM so the document’s classes and theme tokens reach them — no shadow root, no duplicated CSS. Ten are interaction-verified by real clicks and key presses; eleven are registered and defined-only, and registry.js records which is which.

04

Svelte and Angular planned

No source. frameworks/svelte/ARCHITECTURE.md and frameworks/angular/ARCHITECTURE.md set out how each would bind to the same classes, and the parity audit refuses to let a planned entry claim a file. The site renders those tabs as absent rather than showing an empty shell.

05

Retrieval by stack agent surface

An agent asks for a stack and gets the implementation, not a guess: node tools/mue.js stack prints what each framework actually covers; mue show ui-cards --framework vue prints that binding’s source, package, verified note and the contract harvested from the file’s MUE:META block; mue search "switch" --framework react filters by port. A port without a recorded check is reported as unverified.

05 — Why developers keep it in the repo

Less reinventing. More building.

01

Better output from affordable models

A small open-weight model does not have to invent a design system. It retrieves a preview that already resolves contrast, spacing and states, then edits it. That raises the floor — it does not turn a 7B model into a frontier model, and we will not pretend otherwise.

02

Fewer tokens spent on structure

Generation is the expensive part of UI work. When the table, the sidebar and the form already exist as one file path, the prompt becomes “adapt this” instead of “produce 400 lines of markup and CSS”. No fixed saving percentage is published because there is no benchmark behind it.

03

Deterministic starting points

Every resource has an id, a category, a variant list and a path an agent can name in a prompt. mue search "admin sidebar" returns candidates; mue show ui-cards returns the markup. Same input, same retrieval, on every run.

04

One place, licensing already checked no hidden dependencies

Every stack in this repository is the engine’s own work — nothing is vendored from shadcn/ui, Ant Design, Nuxt UI, daisyUI, Flowbite or Creative Tim, and RESOURCES.md records each of them with its license, framework and whether its source is legally incorporable. The only third-party code anywhere on the site is the React and Vue runtimes inside the two committed framework bundles; frameworks/ ships no node_modules.

05

Design systems that travel

Colour, type scale, spacing, radii, shadows and motion are custom properties in one file. Change nine values and every preview follows, in light and dark. Themes are separate files, not find-and-replace.

06

Motion you can turn off with one switch

Hover lift, press depth and reveal distance are composite tokens, and a single reduced-motion block zeroes them. Authors are told not to write their own media queries, so accessibility does not depend on whoever generated the page.

07

Agent-oriented by default

AGENTS.md sets the rule, SKILL.md packages it for skill-aware agents, and mue registry --json exposes the whole library as one machine document. Works with any agent that can read files or run a command — OpenCode, Codex, Claude Code, Cursor, or a plain terminal.

08

Audited, not asserted

Each catalog entry carries its own verification note: WCAG AA contrast in light and dark, no overflow at 375, 768 and 1280. mue check fails a page that references a class the sheet does not define — so drift is caught, not discovered in production.

06 — How it works

Six steps from “make it look good” to a page that does.

  1. STEP 01

    Explore the library

    Filter 54 previews by kind, category or what the screen looks like.

  2. STEP 02

    Find the resource

    Every entry has an id, variants, the tokens it uses and its audit note.

  3. STEP 03

    Inspect the running page

    Open the live preview, switch device width and theme, read the source.

  4. STEP 04

    Hand it to your agent

    Point the agent at the path, or let it call mue show itself.

  5. STEP 05

    Install what you need

    mue add ui-cards --into ../app copies the component plus the layers it needs.

  6. STEP 06

    Build and test

    Adapt the content, then run mue check in your own project. Reuse is a starting point, not a substitute for testing.

07 — Documentation

Read it in the repository, not in a marketing page.

Four files carry the contract. They are versioned with the code, so they cannot disagree with it.

Repository README SKILL.md AGENTS.md
  • MIT licensed. Original source on the vanilla, React, Vue and Web Components stacks; the only third-party code is the React and Vue runtimes bundled into two preview pages. Attribution obligations are recorded per resource and checked by node tools/audit/framework-parity.mjs.
  • What ships: 33 component previews, 15 worked examples, 6 templates, the token layer, one 120 KB component stylesheet, 14 of those components as React, Vue and Web Components source, the mue CLI and the visual lab.
  • Compatibility: anything that reads files or runs a command. The engine needs no framework; if your app is React, Vue or custom elements, the port is already in the repo, labelled experimental with the check that produced that label.
  • No invented proof: there are no testimonials, no star counts, no download figures on this page. Check the repository instead.
  • Contribute: CONTRIBUTING.md states how a new preview is registered and audited.

08 — Questions

Answered plainly.

No. Every preview is plain HTML, CSS and JavaScript wired to design-tokens/engine.css and styles/components.css. Drop the two files in and copy the unit you need. The framework ports are optional, and even their galleries load nothing from a CDN — the React and Vue bundles are built and committed in the repository.

It is built for the person doing the typing: an agent. The unit of reuse is a whole preview plus its token dependencies plus a CLI that names them, rather than a component API you import.

It produces consistent UI, which is most of the complaint. The model stops inventing structure and starts adapting something audited. Layout judgement, content and brand work are still yours.

For 14 components, yes — React and Vue each have real source in frameworks/, plus a Web Components build of the same set, all sharing the engine stylesheet rather than carrying their own. They are labelled experimental, not stable: they compile and pass a headless-Chrome behaviour run, and have not had a screen-reader, Safari or production-project pass. Svelte and Angular are documented plans with no source files.

No code is vendored from them. The engine borrows the token naming convention from shadcn/ui and RESOURCES.md indexes those libraries with licenses and redistribution status so future imports stay legal. The framework ports are the repository’s own components; the React and Vue runtimes appear only inside the two committed preview bundles.

The library is MIT and free. Premium template packs, install support and agency work are under consideration and are not for sale here — nothing on this page takes money.

Page paths, a coarse country from the host, the referrer hostname and an anonymous id in your browser's storage — enough to see reach and which previews get opened. No IP addresses, no user-agent strings, no page contents. Read the notice.
