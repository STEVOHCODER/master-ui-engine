Documentation · Agent guide

Give your coding agent design resources it can actually retrieve.

An agent does not produce generic UI because it is careless. It produces generic UI because every screen is the first screen, and the fastest answer is the one it has seen most often. Reuse changes the job: instead of inventing a table, it adapts one that already resolves contrast, spacing, states and mobile behaviour.

Three surfaces, one repository

01

Instruction files

AGENTS.md states the rule — reuse a preview, never invent generic UI — plus the token and motion conventions an agent must follow. SKILL.md packages the same knowledge for agents that load skills. Both are versioned with the code, so they cannot drift away from it.

02

The mue CLI

Any agent with a terminal can call it: search for what a screen looks like, show for copy-ready markup, region for the exact CSS of one unit, tokens for custom properties, add to install a component with the layers it needs, check to catch unresolved classes. Every command accepts --json.

03

One machine document

node tools/mue.js registry --json returns all 54 resources with ids, paths, categories, variants, token files, breakpoints and the audit note recorded for each. Feed it into a context window once and the agent stops guessing what exists. The repository also documents how to wrap the CLI as an MCP server if your agent prefers tools over files.

Setup, per kind of agent

Agents that read the repo

Codex, Claude Code, OpenCode, Cursor and Aider all read AGENTS.md (or can be pointed at it). Clone the library next to your project and tell the agent where it is. Nothing to install: the previews are HTML, CSS and JavaScript.

Agents that load skills

Copy SKILL.md into your agent's skills directory. It carries the same reuse rule plus the command surface, so the agent looks for an existing preview before writing markup.

Agents inside another project

Use the installer: node tools/mue.js add ui-cards btn-buttons --into ../app copies the component plus the token and stylesheet layers it depends on, so the copied markup is not orphaned.

agent session
# what exists that looks like this?
node tools/mue.js search "pricing table dark"

# give me the markup and its dependencies
node tools/mue.js show ui-sections --json

# install it into the app
node tools/mue.js add ui-sections --into ../app

# did the agent invent a class?
node tools/mue.js check ../app/index.html

# one document for context
node tools/mue.js registry --json > mue-registry.json

Prompt patterns that work

Generate it for me

  • “Build a modern pricing page with three tiers.”
  • “Make the dashboard look professional.”
  • “Add a nice table with filters.”

Each of these asks the model to invent structure, spacing and states from memory. Output quality depends entirely on how much of that pattern the model has actually seen.

Reuse, then adapt

  • “Run mue search 'pricing tiers', open the top preview, keep its tokens, replace the copy.”
  • “Use styles/components.css#pricing and design-tokens/engine.css. Do not write new colour values.”
  • “Install ui-datatable, then add the export column. Verify with mue check at 375 px.”

The agent now has a named starting point, a fixed dependency list and a verification step — three things the first column leaves to chance.

What reuse does not do

Stated plainly, because the honest version sells better than the inflated one.

!

It does not raise a model's ceiling

A small open model still reasons less well than a frontier model. Reuse raises its floor: the interface starts from something already audited instead of something improvised.

!

It does not remove testing

Components copied into a new project need to be checked in that project. mue check finds unresolved classes and missing metadata; it cannot judge whether your content makes sense.

!

It does not vendor other libraries

No shadcn/ui, Ant Design, Nuxt UI or daisyUI code ships here. The engine borrows the token naming convention from shadcn/ui and keeps a license-checked index of those libraries in RESOURCES.md so future imports stay legal.

!

It is not a design replacement

Brand, hierarchy, copy and information architecture are still human work. What disappears is the repetitive part: the ninth table, the fourth empty state, the third date picker.
